# Bathroom Genius 網頁應用實作計畫

日期：2026-11-06。狀態：階段 1、2 與 4 程式已建立，階段 3 的必要查詢依賴已補齊，其餘評論項目待完成。最新驗證為 157 項後端及 16 項 Chromium 測試通過；實際資料、GPS 與手機／LINE 瀏覽器驗收仍依各階段文件進行。

## 目標與範圍

建立同時支援 Safari、Chrome 與 LINE 內建瀏覽器的繁體中文行動網站。訪客不需 LINE 帳號即可搜尋、閱讀評論及開啟導航；發布與管理評論使用 LINE 登入。網站核心流程不得依賴 LIFF 初始化成功。

首版包含附近搜尋、名稱／地址搜尋、篩選、廁所詳情、導航、評論新增與管理，以及 Bot／圖文選單入口。互動地圖、照片、收藏、推播、一般使用者新增廁所及其他登入方式不列入首版。

## 技術與部署邊界

- 沿用本 repo 的 NestJS、MongoDB 與 LINE Bot；新增前端應用，建議放在 `web/`，使用 pnpm workspace 管理。
- 前端框架在第一階段確定；需支援路由、表單驗證、API 狀態管理與瀏覽器測試。採行動優先的響應式版面。
- 正式環境優先讓網站與 `/api` 使用同一 origin，透過反向代理連接後端，簡化 session 與 Cookie 設定。
- 一般網址是主要可分享入口；LINE URL 作為 LINE 入口。兩者都能還原指定廁所與登入前頁面。
- 地圖首版使用可選的靜態縮圖與 Google Maps 導航連結，無地圖金鑰也能完成核心操作。

## 階段 1：定義契約與建立基礎

實作紀錄與環境待確認項目見 [網頁開發與 API 契約](web-app-foundation.zh-TW.md)。前端採 Vite + TypeScript SPA；真實 LINE 登入已由使用者確認，正式網域、provider／LIFF 與實際資料庫盤點仍依清單驗收。

工作：

- 建立前端目錄、開發指令、環境變數範本與測試配置。
- 確認 HTTPS 網址、LINE channel／provider、允許的 callback URL、LIFF ID，以及 MINI App 或 LIFF channel 的部署方式。
- 確認 LINE 身分在網頁登入與既有 Bot 間的一致性，避免跨 provider 的 user ID 被錯誤視為同一人。
- 定義共用錯誤格式、登入狀態、廁所摘要、評論與分頁資料型別。
- 盤點既有資料量、座標有效性與 2dsphere 索引；確認測試環境有可搜尋的資料。
- 統一未知設施、無評分、標籤及開放時間的顯示規則。

驗收：前後端可在本機啟動；直接開啟詳情路由及重新整理不會 404；API 契約與 LINE 環境設定有文件。

## 階段 2：身分驗證與權限

實作與操作文件見 [LINE 登入與管理員操作](authentication.zh-TW.md)。已提供 session、CSRF／Origin、OAuth／LIFF 後端驗證、作者／管理員守衛、管理員 CLI 及基本登入／登出入口。評論表單與草稿恢復仍依階段 5 進行，LIFF SDK 整合依階段 6 進行。

工作：

- 一般瀏覽器採 LINE Login 授權碼流程，使用 state、nonce 與伺服器端 callback 驗證；LINE 內可使用 LIFF ID token，由後端向 LINE 驗證。兩條路徑統一建立應用 session。
- 驗證 token 的有效期限、目標 channel 與身分；不可使用前端傳入的 user ID 或單純 decode 的內容作為權限依據。
- 建立 User 與 Session 資料模型：外部身分、公開暱稱、角色、建立時間、session 到期時間。一般使用者不可指定角色。
- 使用 HttpOnly、Secure Cookie；設定適合授權返回流程的 SameSite 策略。寫入請求使用 CSRF 防護及 Origin 檢查。
- 登出撤銷 session；登入返回路徑僅接受站內允許的路由。
- 新增必須登入及管理員守衛；評論更新／刪除由資料庫條件一併檢查作者或管理員。
- 新增伺服器端管理員授權與撤銷指令，作為首版管理角色的方式；使用者須先完成 LINE 登入建立應用帳號，再以應用內的使用者 ID 指定目標。
- 處理舊匿名評論：沒有可驗證作者資料者不得自行認領；僅管理員可管理。既有 userId 不直接假定為已驗證 LINE 身分。

管理員指令規格（已實作，須在互動終端確認）：

```text
pnpm admin:grant --user-id <你的應用使用者ID>
pnpm admin:revoke --user-id <你的應用使用者ID>
```

- `admin:grant` 將既有使用者的角色設為 `admin`；`admin:revoke` 將角色還原為 `user`。
- 指令只能由具備伺服器執行權限的維運人員操作，不提供公開 HTTP 入口；第一位管理員也透過此方式設定。
- 驗證使用者 ID 與帳號存在性；執行前顯示目標帳號及角色變更並要求確認，執行後記錄目標 ID、角色變更與時間。重複授權或撤銷應安全地回報無需變更。
- API 權限以後端最新角色為準，撤銷後的後續請求必須立即失去管理權限，不信任前端或舊 session 內的角色快照。
- 一般帳號建立時固定為 `user`，登入或個人資料 API 不接受使用者自行指定角色。

建議新增端點：

| 端點                          | 用途                                               |
| ----------------------------- | -------------------------------------------------- |
| `GET /api/auth/csrf`          | 建立或讀取 session 的 CSRF token，供登入及寫入使用 |
| `GET /api/auth/line/start`    | 啟動外部瀏覽器 LINE Login                          |
| `GET /api/auth/line/callback` | 驗證授權結果、建立 session、返回站內頁面           |
| `POST /api/auth/line`         | 驗證 LIFF ID token 並建立相同 session              |
| `GET /api/auth/me`            | 取得目前登入者                                     |
| `POST /api/auth/logout`       | 撤銷 session                                       |
| `GET /api/me/reviews`         | 階段 3 實作：分頁取得自己的評論及廁所摘要          |

驗收：拒絕偽造／過期憑證；未登入寫入回傳 401；非作者操作回傳 403；一般使用者無法修改廁所；登入後可返回原站內詳情路由。評論表單與登入草稿恢復明確歸階段 5，不計入本階段已完成的驗收。

管理員指令驗收：可對既有帳號授權及撤銷，無效 ID 或不存在帳號不造成資料變更；撤銷後立即拒絕管理操作，且保留角色變更紀錄。

## 階段 3：完成網頁需要的查詢與評論 API

進度：階段 4 所需的附近分頁、Bot 第 1 頁、穩定排序及安全文字搜尋已實作；我的評論及評論寫入／彙整項目仍待完成，不將整個階段 3 標記為完成。

工作：

- 直接擴充 `GET /api/toilets/nearby` 支援多頁查詢，不新增搜尋端點；固定路由必須宣告在 `:id` 路由之前。
- 介面接受經緯度、半徑、評分、衛生紙、無障礙、標籤及 `page`、`limit`；預設 `page=1`、`limit=10`、半徑 1 公里，沿用最大半徑 10 公里與每頁 100 筆上限。`page` 必須為大於等於 1 的整數。
- 使用距離加 `_id` 作為確定排序，以 `(page - 1) * limit` 計算略過筆數；回傳 `{ data, total, page, limit, hasMore }`，其中 `total` 為相同位置、半徑及篩選條件下的總筆數。資料異動時不保證跨頁快照一致，可能出現項目移動；超出最後一頁回傳空 `data` 與 `hasMore=false`。
- 同步調整 LINE Bot 對 `ToiletsService.findNearby()` 的呼叫，明確指定 `page=1`、`limit=5`，從分頁結果的 `data` 建立推薦卡片及判斷空結果，不提供後續頁面。Bot 的半徑 1 公里與最低評分預設維持原有行為。
- 網頁不傳評分時不限制分數；明確設定最低分時，保留未評分廁所並於介面說明。
- 無定位時沿用文字搜尋，不宣稱距離排序；限制搜尋長度並跳脫正規表示式特殊字元。
- 評論文字上限 1,000 字，空白評論不可單獨送出。至少提供一項評分或非空白文字。
- 評論公開名稱由受控欄位取得，匿名顯示不移除後端作者關聯；回應不得洩漏 session 或 LINE 身分資料。
- 新增我的評論所需索引；評論寫入後等待評分彙整完成。定義彙整失敗的修復方式，測試並行寫入後的統計一致性。
- 衛生紙回報只保留在評論，不自動覆寫廁所屬性。
- 更新 Swagger 與呼叫端遷移說明：`/nearby` 回應由陣列改為分頁物件，屬於契約變更；網站、Bot 服務及相關測試須同步更新。

驗收：同一 `/nearby` 可查詢第 1、2 頁及超出範圍的頁面，排序與總數正確、參數驗證正確；Bot 僅使用第 1 頁、最多 5 筆，推薦與無結果流程正常；評論新增／編輯／刪除後平均分與總數正確；沒有評分的資料不會顯示為零顆星。

## 階段 4：搜尋與詳情介面

已實作，詳見 [搜尋與廁所詳情](search-and-detail.zh-TW.md)。前後端建置、157 項後端及 16 項 Chromium 測試通過；實際資料、GPS 與手機／LINE 瀏覽器手動驗收待完成。

路由：`/`、`/toilets/:id`。

工作：

- 首頁提供「使用目前位置」、名稱／地址搜尋、半徑與設施篩選。
- 使用者主動觸發定位；定位遭拒或逾時可重試，仍能使用文字搜尋。
- 顯示載入、空結果、無定位、查詢失敗與載入更多狀態。擴大半徑與清除篩選需由使用者觸發。
- 篩選放入 URL；精確定位不放入可分享 URL 或分析事件。返回列表時透過記憶體或 sessionStorage 還原位置、結果與捲動狀態。
- 取消或忽略過時請求，避免快速切換篩選時顯示舊結果。
- 詳情顯示地址、地標、備註、開放時間、設施三態、評分與評論分頁。
- 導航使用 Google Maps walking URL；距離明確標示為直線距離。
- 無效／已刪除廁所提供返回搜尋入口；縮圖失敗不影響操作。

驗收：從一般網址可完成搜尋至導航；定位被拒仍能找到文字結果；返回列表可恢復狀態；LIFF 不可用時所有公開功能正常。

## 階段 5：評論與我的評論介面

路由：`/toilets/:id/review`、`/me/reviews`，另提供自己的評論編輯入口。

工作：

- 評論表單提供以下欄位：
  - **乾淨度評分**：選填，1～5 星，評估廁所清潔程度；未填不計入平均乾淨度，不視為 0 分。
  - **便利度評分**：選填，1～5 星，評估廁所是否好找、方便使用；未填不計入平均便利度，不視為 0 分。
  - **衛生紙狀態**：選填，可選「有衛生紙」（`true`）、「沒有衛生紙」（`false`）、「不確定／未回報」（`null`），預設為 `null`。僅記錄該則評論的觀察，不直接覆寫廁所屬性。
  - **文字評論**：選填，上限 1,000 字；僅有空白不算有效內容。
  - **公開匿名選項**：可選擇以匿名名稱顯示；後端仍保留作者身分，用於編輯、刪除及權限檢查。
- 送出條件：乾淨度評分、便利度評分或非空白文字評論，至少提供一項；只回報衛生紙狀態不能送出。
- 未登入時先登入，返回後恢復草稿；草稿儲存在當前瀏覽器 session，發布或登出後清除。
- 提交中停用重複操作；成功後刷新詳情、評論及我的評論資料。
- 顯示自己的評論操作；刪除前確認，失敗時保留內容。
- 處理 session 過期、廁所已刪除、評論被移除及無權限等狀態。

驗收：使用者可新增、編輯及刪除自己的評論；不能操作他人資料；登入過程不遺失草稿；回到詳情後看到更新的分數。

## 階段 7：測試與上線

必要測試：

- 後端整合測試使用具備真實 geospatial 行為的測試 MongoDB，覆蓋分頁、作者檢查、管理員限制與統計更新。
- 瀏覽器端到端測試覆蓋搜尋、定位遭拒、篩選、登入返回、評論 CRUD 與無效深層連結；自動化可模擬 LINE 回應，實機另驗證真正授權流程。
- 實機矩陣：iOS Safari、Android Chrome、iOS LINE、Android LINE。
- 檢查 44px 主要點擊區、表單標籤、鍵盤焦點、對比及小螢幕版面。
- 設定 HTTPS、靜態路由 fallback、正式 Cookie、CORS allowlist、登入及寫入速率限制、API request ID 與錯誤記錄。
- 記錄不含 token、評論草稿及精確定位。地圖金鑰依用途限制，LINE secret 僅在服務端。
- 新增 readiness endpoint 檢查 MongoDB；保留現有 health endpoint 作存活檢查。
- 先在 staging 完成資料備份與相容性檢查，再部署正式版；Bot 入口切換安排在網站與登入驗證通過之後。
- 回滾應能還原前端與 Bot 入口；權限修補不得回滾成信任未驗證 token 的行為。資料變更採向後相容方式。

上線門檻：四種環境完成訪客搜尋、詳情、導航與登入評論流程；未授權寫入測試通過；無效 LINE SDK 不阻擋公開功能；無阻斷性錯誤。

## 建議 PR 拆分與依賴

1. API 契約、環境設定與前端骨架。
2. LINE 身分、session、權限、管理員授權／撤銷指令與舊資料處理（依賴 1）。
3. 網頁搜尋分頁、我的評論與評論契約（依賴 1、2）。
4. 搜尋及詳情頁（依賴 1、3）。
5. 登入返回、評論及我的評論頁（依賴 2、3、4）。
6. Bot／圖文選單與 LINE 深層連結（依賴 4、5）。
7. 跨瀏覽器驗收、部署設定與操作文件（依賴前述功能）。

每個 PR 必須能獨立驗證，功能未完成時以入口控制避免提前對外曝光。實作前優先確認 LINE channel／provider 與正式網域，其餘可先在本機完成。
